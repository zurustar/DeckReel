# DeckReel 要件：PowerPointからナレーション動画を生成するCLI

## 1. 目的と対象

macOS上で、発表者ノート付きの `.pptx` を1本の解説動画に変換する。
Microsoft PowerPointがインストールされ、利用可能であることを前提とする。
初期版はローカルで実行するCLIとし、GUI、Webサービス、クラウドへの資料送信は対象外。
macOSによるPowerPoint操作の許可など、初回のOS権限付与は必要になり得る。

## 2. 配布と技術方針

- 実装言語の第一候補はGo。外部プロセス制御、ZIP/XML処理、配布の容易さを重視する。
- 利用者が配置・起動する本体は単一バイナリを目標とする。
- Python、Go、Rustなどの言語ランタイムや開発環境を利用者に要求しない。
- PowerPoint、macOS標準機能、ローカルで起動済みのVOICEVOX Engineへの依存を許容する。
- VOICEVOX Engineを除く動画処理等の追加ツールを利用者に個別インストールさせない構成を目標とする。依存ツールの埋め込みと実行時展開も候補とする。
- FFmpeg等の採否、ビルド構成、ライセンス、配布容量、署名・公証への影響は技術検証で決める。
- 単一バイナリ配布と外部ツールの完全不使用は別要件として扱う。実現が難しい場合は依存追加前に方針を見直す。
- Apple Siliconを初期対象候補とする。Intel対応と最低macOSバージョンは未決定。

## 3. 入出力

入力は `.pptx`。発表者ノートをスライドごとの読み上げ原稿として扱う。
初期版では非表示スライドを除き、プレゼンテーションの順序で処理する。
ノート内の本文を抽出し、ページ番号、ヘッダー、フッター等を混入させない。

出力はMP4、H.264/AAC、1920×1080、30fps。
16:9以外のスライドは縦横比を維持して余白を付ける。
スライド内のアニメーション、埋め込み動画、画面切り替え効果は再現せず、静止画として扱う。
入力ファイルは変更しない。既存の出力ファイルは明示的な上書き指定なしに置換しない。

## 4. 処理

1. 入力、PowerPoint、音声・動画処理機能、出力先を確認する。
2. PPTXからスライド順序と発表者ノートを抽出する。
3. PowerPointを利用して各スライドの静止画を得る。直接画像出力かPDF経由かは実機検証で選定する。
4. ノートからスライドごとの音声を生成する。
5. 静止画と音声を組み合わせ、スライドごとの動画クリップを生成する。
6. クリップを順に結合し、完成したMP4を出力する。

初期版は逐次処理でよい。PowerPointのフォント・レイアウトをできるだけ維持し、画像品質は実資料で検証する。完全一致を無条件に保証しない。

## 5. 読み上げと尺

- 音声合成はローカルのVOICEVOX Engineを採用する。macOS標準の読み上げは使用しない。外部クラウドAPIの契約は不要とする。
- 初期版ではEngine・音声モデルを同梱せず、利用者が別途インストール・起動する。DeckReel本体は単一バイナリ配布を目指す。
- 利用可能な音声の選択と読み上げ速度の指定を可能にする。
- 話者・スタイルと速度を明示して生成し、Engineに接続できない場合や指定音声がない場合は停止する。他の音声への自動切り替えはしない。
- 音声ごとの利用条件・クレジットを確認できるよう、生成時の話者・スタイル情報を保持する。
- 読みの補正は任意の辞書ファイルによる文字列置換とする。置換順を固定し、原文を保持する。
- 改行や空白は読み上げ向けに整理する。専門用語の意味や原稿の内容を自動で書き換えない。
- 空のノートは既定で3秒の無音とする。設定によりそのスライドを除外できる。
- 音声終了後に既定で0.5秒の余白を付ける。空ノートの3秒には追加しない。
- クリップ尺は音声長と余白から算出する。フレーム境界への丸めで音声末尾を切らない。

## 6. 再実行と中間成果物

- 作業ディレクトリにスライド画像、原稿、音声、動画クリップ、処理状態を保存する。
- ファイル名の具体的な形式は実装で決める。スライドとの対応を追跡できればよい。
- 原稿、画像、音声設定、出力設定の変更に応じて必要な工程だけ再実行する。
- 原稿だけの変更では既存画像を再利用できるようにする。
- PPTX変更後は必要に応じて全体を書き出してもよいが、同一画像の後続処理は再利用する。
- 失敗時はスライド番号と工程、理由を表示し、成功済みの成果物を保持する。
- 壊れた中間成果物を成功として扱わない。完成前のファイルは一時ファイルとして扱う。
- 対象スライドが0枚の場合は、理由を表示して終了する。

## 7. 結合

全クリップの映像・音声形式を統一し、再エンコードなしのストリームコピーによる結合を目標とする。
結合後の音声同期、スライド境界、最終尺を検証する。
処理時間は入力枚数、尺、実行環境によるため固定の秒数を保証しない。

## 8. 初期版の完了条件

- 日本語ノート付きの複数スライドから、順序どおりのMP4が生成される。
- 図版と文字の表示、音声末尾、スライド境界をMac実機で確認できる。
- 空ノート、16:9以外、非表示スライドを上記の方針で処理できる。
- 原稿の一部変更時に無関係な音声・クリップを再生成しない。
- 中断・失敗後に再実行して、成功済みの処理を再利用できる。
- 単一バイナリの配布方法と、残る環境依存が説明されている。
